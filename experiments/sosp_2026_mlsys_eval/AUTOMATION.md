## 建议推进顺序

1. 先统一正式报告模板、全文输入范围和章节展示，让现有自动流程稳定生成可读报告。
2. 再统一逐篇阶段状态、超时、重试及缓存，使失败恢复无需人工拆批。
3. 增加会议来源与批量 PDF 补传入口，集中处理下载验证问题，复用现有 SQLite 标识合并与偏好规则。

PDF、实际生成报告、SQLite、凭据及运行日志保留在本地，不纳入本记录或 Git。本文不将下载验证问题误判为模型能力问题，也不声称上述自动化改进已实现。

## 完成记录与补充问题

- 本批 10/10 篇生成成功，输入为已核对标题的 10 份 PDF，共 180 页。9 份为用户提供的出版版本，TensorHub 使用公开预印本。
- 全部分析已导入实际 SQLite；导入前做一致性备份，保留原评分、收藏、不感兴趣与交付状态。日期窗口采用分析完成日期，会议发布日期另存，二者不混用。
- 临时导入脚本曾从全文参考文献中误识别本论文的 arXiv 标识。最终核对发现后，改为只检查首页，并修正该条元数据及派生标识；检查确认没有把其他论文并入该实体。这说明标识发现需要受位置和来源约束，不能对全文做无条件正则匹配。
- 模型机制叙述需要核对操作对象、顺序和边界；本批重点检查了噪声取平均与完全替换、固定锚点与移动区域、异步一致切分点与同步屏障等类型的区别。
- 结果核对还应区分实测与推算、最高与平均、不同基线下的加速比。需要自动化证据追溯，不能把一次生成或 JSON 解析成功当作事实准确性验证。
- 最终报告含中文 TL;DR 和四部分正文。已保存原始模型响应及核对后的版本；没有再调用模型重新评分，也未修改生产模板或服务代码。

## 自动化交付的最低要求

下一步应把来源发现、补传接续、全文解析、报告生成、证据核对、入库和页面展示放到同一任务中，以逐篇持久化状态串联。任务必须可中断恢复，跳过输入指纹相同的成功项，统一显示下载受阻和模型失败，并在导入时校验身份与保留偏好。报告核对可使用内部证据字段辅助：记录机制及主要数字对应的正文段落，对外仍维持四部分和 TL;DR，不增添冗长章节。当前只汇总问题和验收结果，具体实现留待后续开发。

## 2026-10-14 实施记录：正文、流式请求与阅读页面

### 已完成

- 正式深度分析移除 15,000 字符及 PyMuPDF 前 20 页限制。仅在可靠识别章节标题后裁去参考文献和附录尾部；无法确定时保留。Discussion / Limitations 暂保留，避免不可靠分段误删正文。超长附录导致参考文献位置较早时，使用编号引用证据辅助识别。记录原始字符数、发送字符数、裁剪范围与选择版本。
- 输入预算包含正文和提示词，以 UTF-8 字节加消息开销保守估算；默认 196608，超限明确失败，不静默发送前缀。该预算不代表已确认供应商支持 256k，应按实际模型上下文为推理和输出留空间。单次输出上限 32768 tokens。
- 正式深度分析使用可取消的异步流式传输，默认首个有效片段等待 180 秒、连续无进展 120 秒、单次总耗时 1200 秒。推理片段计进展但不保存推理正文；保活、空片段不计进展。每 45 秒有事件到达时汇总阶段和字符数，不打印响应正文。
- 超时、断流、输出不完整及瞬态网络错误关闭连接并释放论文处理位置，依托已有 SQLite 失败阶段保留供后续任务重试。本阶段不叠加 SDK / LLM 内层重试；其他可重试的分析错误仍由论文层有限重试。单进程内，同一服务和模型连续三次流式故障进入 60 秒冷却。冷却不是跨进程持久状态。
- 保留 Chat / Responses 端点能力判断，支持两种流式事件；未知来源分析和摘要降级不展示全文 TL;DR。更改正文选择策略时仅更新分析阶段输入指纹，未重新评分现有论文。
- 论文检索中的来源变体直接展示中文标题、TL;DR 与四部分正文，支持编号、加粗、旧列表和其他自定义字段，空字段省略、内部元数据隐藏。模型 HTML 转义后展示；英文界面切换不翻译报告正文。有 PDF 分析的论文不再显示仅摘要复评提示。
- 高级设置支持上述超时和预算字段的加载、编辑、保存与校验。README 中英文说明及截图同步；截图只含虚构论文。
