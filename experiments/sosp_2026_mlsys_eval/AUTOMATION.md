# SOSP 全文报告流程：自动化问题记录

记录日期：2026-10-14。本次范围为此前确认通过的 10 篇论文；使用已认可的中文四部分全文报告模板和 `deepseek-reasoner`。本文记录实际遇到的问题与建议，尚未将这些建议实现为正式工作流。

## 已观察到的问题

| 问题 | 本次证据与影响 | 后续处理建议 |
|---|---|---|
| ACM 自动下载被验证页面阻挡 | 8 篇论文的 ACM PDF 入口均返回 HTTP 403；用户在浏览器确认是检测自动访问的页面。开放访问元数据并不等于程序能直接下载 | 区分验证拦截、登录要求、网络失败与链接失效；集中显示待补下载清单，支持用户补传后恢复。认证应通过受支持的浏览器流程，不能要求用户交出密码或把 Cookie 写进日志 |
| 元数据有链接，仍缺可直接下载的公开全文 | Semantic Scholar / OpenAlex 多数返回同一个被阻挡的 ACM 链接；部分作者页面只有论文列表，没有 PDF 链接。TensorHub 可从公开 arXiv 预印本获得 | 建立一次性的来源发现流程，统一检查出版商、预印本与作者公开版本；记录候选与失败原因，避免代理逐篇临时搜索。用 DOI、标题、作者核对不同版本 |
| 正式深度分析只使用正文前缀 | 当前 `AnalysisAgent.deep_analyze` 构造输入时使用 `pdf_text[:15000]`；本次单篇提取文本远大于此值，设计和结果可能位于截断部分 | 按模型上下文预算选择完整正文或关键章节；优先 Introduction，但不能丢掉核对机制和结果所需的正文。记录实际发送范围，不能把前缀分析展示成已读完整论文 |
| 长推理请求超时及重复消耗 | 初次 SANDHI 请求最终报告 `APITimeoutError`，约 601 秒后结束；单次配置超时 300 秒且 SDK 有重试。随后将 SDK 超时放宽为 900 秒，ACDC 与 SANDHI 的非流式请求仍在约 600 秒后以 `APIConnectionError` 结束，具体中间层尚未定位。TensorHub 首次成功约 284 秒，Anchor 约 567 秒 | 使用适合全文推理的超时与可观察的调用状态；明确应用层和 SDK 重试职责，避免两层重复。保留每次尝试、耗时、用量与失败类型，超时不能当作论文不相关 |
| 实验模板尚未进入正式生成流程 | 本次使用实验模板 v1.3；生产深度分析模板和运行配置未切换 | 迁移时统一正式模板、字段校验、中文 TL;DR 与模板指纹，区分评分、摘要翻译和全文分析缓存；不要为更新总结而重新评分全部论文 |
| 页面尚未按四部分展示全文分析 | 当前论文检索的深度分析区域直接以 JSON 展示 `variant.analysis` | 按章节和 Markdown 展示中文内容，支持编号与加粗；缺项自然省略，保留全文来源标识，不强求条目数量 |
| 会议论文入库仍依赖独立脚本 | 本次调用历史库的 `import_legacy_paper` 契约导入完整元数据、旧评分和新分析；这提供兼容导入，但不是正式会议来源任务 | 建立会议论文导入入口，复用论文标识合并、分阶段持久化、任务锁及查询规则。保留既有评分、收藏与不感兴趣状态，不伪造每日交付记录 |
| 批次状态需要统一管理 | 本次先处理已有全文，再处理补传论文，并单独重试超时项；批次各自写总状态时可能覆盖其他批次进度 | 用数据库保存逐篇、逐阶段状态，统一汇总任务；按论文与输入指纹加活动锁，支持重启、跳过成功项、失败单项重试及增量补传，不再靠手工拆脚本 |
| 模型输出仍需要机制与数字核对 | TensorHub 初稿混入英文叙述，并将主动撤销发布时的版本保留说得过宽；核对正文后澄清，原始响应保留 | 做字段、语言、截断和来源检查；重点核对机制动词与收益倍率。自动检查无法保证论文事实准确，必要时标记待核查，不能静默改写原始响应 |

## 建议推进顺序

1. 先统一正式报告模板、全文输入范围和章节展示，让现有自动流程稳定生成可读报告。
2. 再统一逐篇阶段状态、超时、重试及缓存，使失败恢复无需人工拆批。
3. 增加会议来源与批量 PDF 补传入口，集中处理下载验证问题，复用现有 SQLite 标识合并与偏好规则。

PDF、实际生成报告、SQLite、凭据及运行日志保留在本地，不纳入本记录或 Git。本文不将下载验证问题误判为模型能力问题，也不声称上述自动化改进已实现。

对失败项 ACDC 与 SANDHI 尝试标准流式调用，已收到持续的推理片段。进度日志只记录片段长度与阶段，不记录推理正文或凭据。ACDC 与 SANDHI 流式重试分别约 633 秒与 901 秒后完整成功，均超过此前约 600 秒的非流式断开时间。本批 10/10 篇最终成功，但这只是独立批次的恢复验证，正式流程尚未采用该实现。

## 完成记录与补充问题

- 本批 10/10 篇生成成功，输入为已核对标题的 10 份 PDF，共 180 页。9 份为用户提供的出版版本，TensorHub 使用公开预印本。
- 全部分析已导入实际 SQLite；导入前做一致性备份，保留原评分、收藏、不感兴趣与交付状态。日期窗口采用分析完成日期，会议发布日期另存，二者不混用。
- 临时导入脚本曾从全文参考文献中误识别本论文的 arXiv 标识。最终核对发现后，改为只检查首页，并修正该条元数据及派生标识；检查确认没有把其他论文并入该实体。这说明标识发现需要受位置和来源约束，不能对全文做无条件正则匹配。
- 模型机制叙述需要核对操作对象、顺序和边界；本批重点检查了噪声取平均与完全替换、固定锚点与移动区域、异步一致切分点与同步屏障等类型的区别。
- 结果核对还应区分实测与推算、最高与平均、不同基线下的加速比。需要自动化证据追溯，不能把一次生成或 JSON 解析成功当作事实准确性验证。
- 最终报告含中文 TL;DR 和四部分正文。已保存原始模型响应及核对后的版本；没有再调用模型重新评分，也未修改生产模板或服务代码。

## 自动化交付的最低要求

下一步应把来源发现、补传接续、全文解析、报告生成、证据核对、入库和页面展示放到同一任务中，以逐篇持久化状态串联。任务必须可中断恢复，跳过输入指纹相同的成功项，统一显示下载受阻和模型失败，并在导入时校验身份与保留偏好。报告核对可使用内部证据字段辅助：记录机制及主要数字对应的正文段落，对外仍维持四部分和 TL;DR，不增添冗长章节。当前只汇总问题和验收结果，具体实现留待后续开发。
